> 这是工程上的风险分级参考，不是法律意见；最终以现行法条与有权机关认定为准。

## 一、法条对照表（按"行为类型"而不是"技术名词"对照）

| 法条 | 规制的行为 | 构成要件关键点 | 对应工具能力 | 风险 |
|---|---|---|---|---|
| **刑法 285 条 1 款**<br>非法侵入计算机信息系统罪 | 侵入**国家事务/国防/尖端科技**领域系统 | 对象特定 + 侵入 | 本工具无定向能力 | 无关 |
| **刑法 285 条 2 款**<br>非法获取计算机信息系统数据罪 | 侵入上述之外系统，或采用其他技术手段获取数据 | **未经授权** + 技术手段 + 获取数据 + 情节严重 | **向第三方服务器发包并取回执**（NET_SEND） | 🔴 高 |
| **刑法 285 条 3 款**<br>提供侵入、非法控制计算机信息系统程序工具罪 | 提供**专门**用于侵入/非法控制的程序工具 | 专门性 + 明知他人用于违法 | **frida 注入真机 + 收割设备签名**（LIVE_HARVEST） | 🔴 极高 |
| **刑法 286 条**<br>破坏计算机信息系统罪 | 对系统功能/数据/应用程序删改干扰致不能正常运行 | 后果严重 | 发包干扰服务 / 真机写入卡密后运行 | 🔴 高 |
| **刑法 217/218 条**<br>侵犯著作权罪、销售侵权复制品罪 | 以营利为目的，未经许可复制发行他人软件 | **营利目的** + 未经许可 + 数额 | **把绕过授权的补丁部署并运行**（DEPLOY_RUN）；禁商用附加条款正是对冲这一要件 | 🔴 高 |
| **著作权法 24 条**<br>合理使用 | 为个人学习、研究、欣赏使用；教学科研少量复制 | 非营利 + 限定范围 | **全部静态分析**：拆包、反编译、字符串、密钥、解密、扫描 | 🟢 低 |
| **著作权法 53 条**<br>规避技术保护措施 | 故意避开/破坏权利人为保护著作权采取的技术措施 | 故意 + 技术措施 | patch_scan / auth_scan（**识别**）合法；patch_apply（**实施**）高度敏感 | 🟡 中 |
| **网络安全法 27 条** | 不得非法侵入他人网络、干扰服务、窃取数据，也不得提供技术支持 | 网络层面 + 帮助行为 | 发包、注入、部署三类；作者侧"不提供帮助"由授权审阅+拒绝记录证明 | 🔴 高 |
| **反不正当竞争法 12 条**<br>互联网专条 | 利用技术手段破坏他人网络产品/服务正常运行 | 妨碍、破坏 | 批量发包 / 高频重放（`replay` 已限 0.1s 间隔、max_rounds=2） | 🟠 中高 |
| **计算机软件保护条例 24 条** | 故意避开/破坏技术措施 | 故意 | 同著作权法 53 条 | 🟡 中 |
| **数据安全法 / 个人信息保护法** | 非法获取、加工、传输他人数据与个人信息 | 数据/个人信息 + 非法 | 抓包产物含 token/设备信息 → 必须本地保存、不外传 | 🟠 中高 |

## 二、决定加锁边界的三个法律判断

### 判断 1：「分析」和「对外产生效果」是分水岭

- **读取、识别、拆解、解密、扫描、生成报告** —— 作用对象是使用者**自己持有的文件**。
  对应《著作权法》24 条学习与研究豁免，本身中立；作者"帮助开发者加固自己产品"的目的
  也不含违法故意。
- **发包、注入、部署运行** —— 作用对象变成**他人的服务器或他人的设备**。
  这一步才可能落入 285 条、286 条、网安法 27 条。

**所以：只锁后者。前者全部正常开放。**

### 判断 2：「方案」不等于「实施」

`fakepacket_build` 生成的是**假包方案**（报告 + 脚本，默认 DRY=1），不涉及真实网络请求。
法律上属于准备工具/分析，尚未实施。因此：
- `send=false`（默认）→ **不锁**
- `send=true`（真发包）→ **锁 NET_SEND**

`replay(dry_run=True)` → 只构造请求预览 → **不锁**；
`replay(dry_run=False)` → 真发包 → **锁 NET_SEND**。

### 判断 3：作者责任看的是「专门性」与「明知」

285 条 3 款的入罪核心是**"专门"用于侵入/非法控制** + **明知他人用于违法**。
对冲方式不是把工具锁死，而是：

1. 工具**通用**、不针对任何特定商业软件（现有代码已做到）；
2. 默认**不提供**违法能力（本次加锁）；
3. 对高危能力实行**逐例声明 + 人工审阅 + 记录留痕**（本次实现）；
4. 拒绝违法定制请求并留存（DISCLAIMER 第九、十节已写入）。

这四点齐备，"专门性"与"明知"两个要件都难以成立。

## 三、能力分级结论（技术实现依据）

### L0 · 完全开放（无需授权，占绝大多数）

```
apk_info / apk_unpack / dex / elf / pe / native / disasm / functions
ghidra_decompile / identify / zip_password / xor / keys / strings
annotate / deps / scan_any / unpack_any / repack_any / carve / segments
garble / decrypt_auto / decrypt_save / keys_any / cipher_profile
auth_scan / patch_scan / patch_plan / auth_apply(dry_run=true)
fakepacket_build(send=false) / fakepacket_capture / fakepacket_save
fakepacket_build 生成的 DRY 脚本 / 所有报告与落盘
```

法律依据：著作权法 24 条（学习研究）、技术中立、未对外产生效果。

### L1 · 加锁（需声明 → 作者审阅 → 联网校验解锁）

| 能力 ID | 覆盖的操作 | 法条 |
|---|---|---|
| `NET_SEND` | `fakepacket_build(send=true)`、`replay(dry_run=false)`、`_post()` 真发包 | 285 条 2 款、286 条、网安法 27、反不正当竞争法 12 |
| `LIVE_HARVEST` | `fakepacket_live()` 的 frida 分支、`install_card()`、`run_live()` 真机分支 | 285 条 3 款、286 条、网安法 27 |
| `DEPLOY_RUN` | `patch_install()`、`patch_launch()`、`auth_apply(dry_run=false)` 后部署运行 | 217/218 条、著作权法 53、软保条例 24 |

**离线分支不锁**：`fakepacket_live(capture_log=...)` 只解析用户自己抓的日志，
不碰他人设备 → 归 L0。`auth_apply(dry_run=true)` 只预演 → 归 L0。

### L2 · 不提供

- 针对任何**具体第三方商业软件**的预制破解配方
- 大规模扫描 / 对第三方服务压测 / 绕过付费墙的现成开关

`DISCLAIMER.md` 第九、十节与 AGPL 附加条款已明确禁止，代码层面不实现。

## 四、为什么用"联网校验"而不是纯离线签名

离线签名（私钥签发的码永久有效）有一个法律弱点：**作者无法逐例审阅**，
一旦签发出去就无法撤回，与"明知/专门性"的抗辩相冲突。

联网校验方案：

```
使用者本地（多层加密的能力模块，明文不落盘）
   │  ① 生成申请：能力ID + 机器指纹 + nonce + 时间戳 + 用途声明（中文）
   │  ② 只发送这个"请求哈希格式"到作者电脑（隧道）
   ▼
作者电脑（私钥不出本机，运行 gate_server.py）
   │  ③ 人工审阅用途 → 同意/拒绝 → 用私钥签发短期解锁令牌
   ▼
使用者本地
   ④ 收到令牌 → 验签 → 才用令牌派生密钥解密能力模块 → 运行
```

这样每次启用都是**一次人工审阅**，且令牌短期有效、绑定机器、可撤销——
"逐例审阅 + 记录留痕"从文档承诺变成了**系统事实**。

## 五、结论一句话

> 逆向分析能力全部开放；只有"向他人服务器发包、向他人设备注入、把绕过授权的程序部署运行"
> 这三类需要逐例声明和作者审阅；这是技术分级，也是把作者从 285 条 3 款的风险里摘出来的必要设计。
